# House-rules survey brief

You are surveying fan-made rulesets for "Dark Souls: The Board Game" stored in a Google Drive folder. You have Google Drive tools (load them with ToolSearch: `select:mcp__Google_Drive__read_file_content,mcp__Google_Drive__get_file_metadata`; call `read_file_content` with the file id). Read each file assigned to you and write ONE report file. Change nothing else.

## Why

The rulebook's author wants an encounter round in which **all enemies act, then all characters act** (the published game instead has every enemy act after each single character's turn, which is slow). The open design problem is **how to keep that round balanced for one to four characters**, simply and intuitively. The author may fall back to the published alternating structure if no clean answer exists. Find what other designers did.

## For every file, extract (quote closely, with the page or heading; write "nothing" where the file is silent)

1. **Round structure:** who acts when in a normal encounter and in a boss fight (all enemies then all players? enemy after each player? something else? can players choose their order?).
2. **Scaling with the number of players:** anything that changes with player count: enemy health, damage, number of activations, number of enemies, number of party actions, souls, sparks, treasure. Give the exact numbers or formula.
3. **Aggro / targeting:** who holds aggro and when it moves.
4. **Player versus player rules,** if any: setup, turn order, how attacks are defended, how it ends, rewards.
5. **Anything else that is unusually simple and clever** (one or two lines each): death and revival, sparks, souls, treasure, dodge, parry, conditions, bosses.
6. The file's own statement of what problem it is solving, in one line.

## Rules for the work

- Write the report incrementally: after EACH file, append its section to your report file, so nothing is lost if you are interrupted. A usage limit applies; do not re-read files; do not read files not assigned to you.
- If a file cannot be read (too large, unsupported, error), try once more, then record "could not be read: <error>" and move on. Some files are in Spanish; report in English.
- Report only what the file says. Do not fill gaps from memory of the published game. Do not give personal data beyond a ruleset's author name or handle as printed.
- End the report with a section **"Best ideas for an all-enemies-then-all-characters round"**: the three to five mechanisms from your files that best solve the balance problem, each with the file it came from and one line on its cost in complexity.
- Final reply to the lead: that closing section, plus one line per file saying what it is.
